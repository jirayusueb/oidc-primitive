The `client_credentials` grant serves confidential clients calling your API on their own behalf ([RFC 6749 s4.4](https://www.rfc-editor.org/rfc/rfc6749#section-4.4)). No user, no browser, no ID token, and no refresh token: the client simply asks again when the access token expires.

## Rules the library enforces

- Client authentication happens first, as in every grant. `ClientSecret.parseBasic` reads the `Authorization: Basic` header; `OpaqueToken.matchesHash` compares against the stored hash. For `private_key_jwt`, use `ClientAssertion.verify` ([Client authentication](/guide/client-authentication/)).
- `Resource.resolveAudience` resolves the `resource` parameters into the `aud` claim ([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)).
- `AccessTokenVerifier.verify` checks `typ`, `alg`, `iss`, `aud` and `exp` per [RFC 9068](https://www.rfc-editor.org/rfc/rfc9068).

## Rules that stay yours

- Only confidential clients may use the grant. A public client (`token_endpoint_auth_method: none`) has no identity to authenticate.
- Drop `openid` from the requested scope: there is no user, so an ID token would be meaningless.
- Decide the token lifetime. Short is fine because there is no refresh token to rotate: the client re-authenticates each time.

```ts
import { OAuthResponse, Resource, Scope, TokenSigner } from 'oidc-primitive';

declare const signer: TokenSigner;
declare const scopesSupported: string[];

const scope = Scope.parse(f.get('scope')).filter((s) => scopesSupported.includes(s) && s !== 'openid');
const access = await signer.signAccessToken({
	sub: client.client_id,
	aud: Resource.resolveAudience(f.getAll('resource'), issuer),
	client_id: client.client_id,
	scope: Scope.format(scope),
});
return OAuthResponse.json({ access_token: access, token_type: 'Bearer', expires_in: 600, scope: Scope.format(scope) });
```

A grant id (`gid` claim in the example OP) is optional. If you issue one, revoking it is your job. See [Host checklist](/guide/host-checklist/).
