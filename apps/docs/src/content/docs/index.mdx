## Every check names its spec

A token endpoint is your route, your storage, and a handful of calls. Each call enforces one rule and throws an `OAuthError` that already knows its HTTP response.

```ts title="token.ts"
import { OAuthError, OAuthResponse, Pkce, Token } from 'oidc-primitive';

export const token = async (form: URLSearchParams): Promise<Response> => {
	try {
		const code = form.get('code');
		if (!code) throw new OAuthError.InvalidRequest('code is required');
		const record = await consumeCode(await Token.hash(code)); // your storage, atomic
		if (!record) throw new OAuthError.InvalidGrant('code is invalid');
		await Pkce.verify(form.get('code_verifier'), record.challenge);
		return OAuthResponse.json({ access_token: await issueAccessToken(), token_type: 'Bearer', expires_in: 600 });
	} catch (err) {
		if (err instanceof OAuthError.OAuthError) return err.toResponse();
		throw err;
	}
};
```

<ul class="op-specmap not-content">
	<li><code>Token.hash</code><a href="https://www.rfc-editor.org/rfc/rfc6749#section-10.10">RFC 6749 s10.10, store hashes, never codes</a></li>
	<li><code>Pkce.verify</code><a href="https://www.rfc-editor.org/rfc/rfc7636#section-4.6">RFC 7636 s4.6, S256 only, downgrade refused (RFC 9700 s4.8.2)</a></li>
	<li><code>OAuthResponse.json</code><a href="https://www.rfc-editor.org/rfc/rfc6749#section-5.1">RFC 6749 s5.1, <code>Cache-Control: no-store</code></a></li>
	<li><code>err.toResponse()</code><a href="https://www.rfc-editor.org/rfc/rfc6749#section-5.2">RFC 6749 s5.2, error code and status</a></li>
</ul>

The test suite follows the same rule: every `describe` block names the RFC or OpenID section it enforces.

## You own the endpoint

The library answers security questions. It never decides who your users are, where your data lives, or what your pages look like.
